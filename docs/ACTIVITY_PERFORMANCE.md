# 角色性能测量

v2.7 优化桌面角色的行为判定、帧期限和自动任务调度。目标是减少无效回调、避免动画延迟不断累积，不改变 PNG、帧数或皮肤作者设定的动作时长。

## 运行探针

在仓库根目录执行：

```powershell
dotnet run --project benchmarks/PerformanceProbe.csproj --configuration Release -- --activity . artifacts/activity/result.json 8
```

最后一个参数为每阶段采样秒数，范围 3-120。依次采样单角色注视、三角色注视、三角色仅随机动作、三角色勿扰、三角色隐藏。使用屏幕外透明原生 WPF 窗口和内存配置，不读取或改写个人角色配置，不注册托盘或全局快捷键；日志输出到报告旁的 `probe-logs`。

探针统计所有角色定时器的 Tick 和图像源变化，记录相对上一帧规定时长的额外间隔 P95、分配量、Private Bytes 和进程 CPU。CPU 百分比按一个核心归一化，不是任务管理器的整机百分比。

比较前后版本时使用相同探针、相同阶段时长，先让其他构建和测试结束。建议重复多次，并保留 JSON 原件；不能用一次短样本宣称固定倍数的 CPU 或电池提升。

## 结果解释

- 仅随机动作时，自动计时器仍可能显示“已启用”，但它是在等待数十秒后的期限，不代表每 100ms 回调。
- 勿扰时保留待机帧动画，自动动作计时器停止；因此总角色回调不为零。
- 隐藏角色的实例定时器停止，但共享学习服务仍会正常计时，整个进程不一定是零 CPU。
- 鼠标注视需要持续采样；更准确的动画期限也可能增加少量提前唤醒后的重试，不能期待所有场景回调数都下降。
- 本探针不衡量屏幕上合成、GPU 利用率、电池耗电或真实多显示器拖动。帧渲染非空、原始像素和原生交互由单独测试检查。
- 桌面 WPF 定时器不是实时系统。新实现纠正的是累计相位漂移；繁忙时可以跳过过期帧，不能保证每一帧都实际显示。

本地对比数据与当前实现的回归结果记录在 `artifacts/activity-v2.7` 和 `artifacts/qa-v2.7.0`，不自动上传这些本机测量数据。

## 本地短样本（2026-09-10）

以下为同一探针每阶段约 8 秒的 v2.6.0 基线与 v2.7.0 本地实现对比。不是统计显著性结果，也不是电池测试。

| 场景 | 角色回调数：之前 / 之后 | 额外帧间隔 P95：之前 / 之后 | 单核 CPU：之前 / 之后 |
| --- | --- | --- | --- |
| 单角色注视 | 116 / 123 | 13.03 / 14.64 ms | 9.38% / 9.57% |
| 三角色注视 | 348 / 375 | 25.86 / 14.17 ms | 4.88% / 5.28% |
| 三角色仅随机动作 | 347 / 157 | 16.11 / 12.41 ms | 4.10% / 1.76% |
| 三角色勿扰 | 346 / 158 | 18.43 / 13.30 ms | 1.17% / 1.76% |
| 三角色隐藏 | 0 / 0 | 无帧变化 | 0% / 0% |

可观察到仅随机动作和勿扰场景的角色回调减少约 55%，但注视场景回调略增，CPU 结果也不是所有场景都下降。本轮可确认的是按期限调度、迟到帧定位与活动抑制的行为变化；是否节省整机电量需要更长、重复、屏幕内的测量。程序界面和原始素材未因此改变。
