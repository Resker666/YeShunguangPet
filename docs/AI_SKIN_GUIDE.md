# 用 AI 制作自己的角色皮肤

皮肤格式适用于叶瞬光桌面宠物 v1.2.0 及以后的版本；ZIP 直导、更新和导出需要 v1.4.0 或更新版本。

制作流程：准备参考资料 → 确认角色定稿 → 生成动作 → 组装和校验 → 导入桌宠。

桌宠负责读取、预览和播放制作完成的皮肤包。新皮肤至少包含两个相互匹配的文件：

```text
MyCharacter/
  pet.json
  spritesheet.png
```

`spritesheet.png` 是按网格排列的动画帧；`pet.json` 告诉程序每个动作在哪一行、从哪一列开始以及播放多久。单张角色立绘不会自动生成其他动作，只修改 JSON 也不会产生新的画面。

## 1. 准备资料和工具

准备以下材料：

- **角色信息**：作品名、角色名；原创角色则写清外观和性格。
- **参考图**：清晰的全身图、脸部图，以及服装、发饰或武器等关键细节。多张图应使用同一套服装。
- **风格要求**：例如 Q 版二头身、精细二次元、像素风；列出必须保留的发型、配色、配饰和道具。
- **技术文件**：[PET_FORMAT.md](PET_FORMAT.md) 和 [默认 pet.json](../Pets/YeShunguang/pet.json)。

将技术文件作为附件提供给 AI；若它不能访问链接，就提供文件内容。其他电脑上的 AI 无法通过你本机的文件路径读取资料。

默认 JSON 仅用于复用布局和播放参数，不是新角色的外观参考。不要把旧角色精灵图当作新角色的身份参考；在现有角色目录之外制作新包，使用新的唯一 id。

完整制作需要两种能力：

- 图片生成：依据参考图绘制同一角色的动作画面。
- 文件处理：提取和对齐帧、处理透明背景、精确拼接 PNG、生成 JSON 并校验。

可以由一个同时具备这些能力的 AI 工具完成，也可以先用绘图工具制作动作条，再交给具备文件处理能力的工具组装。仅能聊天的工具可以协助写提示词和 JSON，但无法直接交付真实动画图片。桌宠运行和导入皮肤不需要 API key。

## 2. 确认目标布局

首次制作建议沿用默认皮肤的布局，以便复用已验证的动作参数：

- 最终 PNG：`1536 × 2288` 像素。
- 网格：8 列、11 行，每格 `192 × 208`。
- 行列从 0 开始，各普通动作从第 0 列开始。
- 最终图像使用真正透明的 RGBA 背景，未使用的格子完全透明。

| 行 | JSON 动作键 | 有效帧数 | 内容 |
| --- | --- | --- | --- |
| 0 | `idle` | 6 | 呼吸、眨眼等轻微待机 |
| 1 | `runningRight` | 8 | 朝屏幕右侧移动 |
| 2 | `runningLeft` | 8 | 朝屏幕左侧移动 |
| 3 | `waving` | 4 | 打招呼 |
| 4 | `jumping` | 5 | 起跳、腾空、落地 |
| 5 | `failed` | 8 | 失败或失落反应 |
| 6 | `waiting` | 6 | 期待、等待 |
| 7 | `running` | 6 | 工作、思考或处理任务 |
| 8 | `review` | 6 | 专注检查 |
| 9 | `lookDirections` 前 8 项 | 8 | 0° 到 157.5° |
| 10 | `lookDirections` 后 8 项 | 8 | 180° 到 337.5° |

注视方向从正上方开始，按屏幕坐标顺时针每隔 22.5° 排列：0° 向上、90° 向右、180° 向下、270° 向左。0° 不是正面待机。所有注视动作应保持角色身体的稳定定位，不能简单旋转整张角色图片来假装转头。

v1.2.0 也支持其他布局。最小皮肤只需要循环的 `idle`；缺少其他动作时，相应菜单或自动行为会禁用。制作简化版时，应按实际图片生成 JSON，不要留下指向空白格子的动作。具体规则见 [格式说明](PET_FORMAT.md)。

## 3. 第一阶段：发给 AI 的完整任务提示词

替换方括号内容，附上参考图、`PET_FORMAT.md` 和默认 `pet.json`，再发送下面的任务。

```text
请为我的 Windows WPF 桌面宠物制作一个 schemaVersion 1 的可导入角色皮肤包。

角色：[作品名 / 角色名，或原创角色描述]
皮肤 id：[唯一的小写英文，例如 my-character]
显示名称：[角色名称]
角色描述：[一句话简介]
风格：[例如 Q 版二头身、精细二次元、保留原服装]
必须保留的特征：[发型、眼睛、配饰、服装、武器等]
不能出现的变化：[例如换装、改发色、添加道具]
参考图：[附上图片并说明各图用途]

请先阅读我提供的 PET_FORMAT.md 和默认 pet.json。
默认 pet.json 仅作为技术模板，角色外观以本次参考图为准。
使用新的角色目录和唯一 id，保留已有皮肤文件。

分阶段制作：
1. 先检查参考资料，整理必须保持一致的角色特征。
2. 只制作一张完整全身角色定稿，等我确认外观后再继续动画。
3. 确认后，所有动作都使用这张定稿作为身份参考。
4. 分动作生成连续帧，再用程序提取、对齐和精确组装。
   不要依靠一次生成整张精灵图来保证网格精度。
5. 完成后展示各动作播放预览和注视方向预览，再交付文件。

最终布局：
PNG 为 1536×2288，8 列×11 行，每格 192×208。
行列从 0 开始，普通动作从第 0 列开始。
第 0 行 idle：6 帧；
第 1 行 runningRight：8 帧；
第 2 行 runningLeft：8 帧；
第 3 行 waving：4 帧；
第 4 行 jumping：5 帧；
第 5 行 failed：8 帧；
第 6 行 waiting：6 帧；
第 7 行 running：6 帧；
第 8 行 review：6 帧。
running 表现工作或思考，runningRight/Left 表现左右移动。
第 9、10 行放 16 个注视方向：
从正上方开始，顺时针每隔 22.5°，先确认上、右、下、左，
再生成连续的中间方向。按屏幕左右判断方向。

画面要求：
保持脸型、发型、配色、服装、身体比例和道具一致。
角色全身完整，动作不能越过所在单元格。
保持合理的统一尺度和基线；跳跃的上下变化来自动作本身。
左右移动要有连贯步态，不能用相同图片重复填充。
若服饰或道具不对称，不要直接镜像导致其位置错误。
最终 PNG 使用真正透明的 RGBA 背景；不画棋盘格、场景、
网格线、文字、帧编号、浮空特效或地面阴影。
未使用的格子完全透明。

文件要求：
交付同一目录中的 pet.json 和 spritesheet.png。
同时交付仅包含这个角色目录的 ZIP，供 v1.4.0 直接导入；
不要将多个角色的 pet.json 或测试清单混入同一个 ZIP。
pet.json 使用 WPF 的 schemaVersion: 1，字段按 PET_FORMAT.md。
沿用默认模板的行列、时长、loop 和 lookDirections，
并更新 id、name、description；spriteSheet 为 spritesheet.png。
不要添加未知字段，不使用 Codex 的 spriteVersionNumber、
displayName 或 spritesheetPath 字段。
本程序的动作键为 runningRight / runningLeft，
不是 running-right / running-left。

校验要求：
实际检查 PNG 像素尺寸、透明背景、帧数与帧坐标。
idle 必须循环；waving、jumping、failed 必须为单次播放。
提供动作预览与校验结果，检查变脸、裁切、闪跳、
不自然的尺寸变化、空白帧以及左右方向错误。
如果工具不能生成图片或处理文件，请明确说明缺少的能力，
不要把文字说明或虚构文件链接当作成品。

现在先完成角色定稿，等待我确认。
```

## 4. 第二阶段：确认外观后继续

先看脸型、发色、服装和配饰是否准确。外观还不满意时，明确指出具体差异，让 AI 调整定稿；通过后再发送：

```text
角色定稿已确认，请将这张图作为后续所有动作的唯一身份基准。
继续按前述布局分动作制作；每一行动作都附上定稿作为参考。
先检查待机和向右移动，确认尺度、脸型和步态一致，
再完成其他动作，以及按屏幕坐标定义的 16 个注视方向。

使用程序将已确认的动作帧组装成 1536×2288 的透明 PNG。
不要用复制同一静帧、整体旋转或任意拉伸来替代缺失动作。
交付前展示逐动作预览，确认普通循环首尾衔接、非跳跃动作
基线稳定、所有帧不越格、注视方向连贯。
同时交付符合 WPF schemaVersion 1 的 pet.json。
```

这里的“用程序组装”处理的是已经生成的画面：保证像素尺寸、单元格位置、透明背景和播放顺序。角色画得是否准确、动作是否自然，仍需检查预览；提示词不能保证一次生成就全部正确。

## 5. 第三阶段：验收成品

请 AI 提供实际文件和播放预览，然后检查：

- 目录中存在 `pet.json` 和它引用的 `spritesheet.png`，名称不是 `pet.json.txt`。
- PNG 实际尺寸符合清单，背景真正透明；棋盘格图案不是透明背景。
- 每个动作中角色脸型、服装和道具一致，手脚、头发、武器没有切出格子。
- 待机有轻微变化；移动有步态；工作动作与移动动作含义不同。
- 普通循环没有突然变大变小或左右闪跳，跳跃能自然落回原位置。
- 上、右、下、左注视方向明确，中间方向连贯。
- 新包使用独立的 id，例如 `my-character`，不要继续用 `ye-shunguang`。

程序能检查文件格式、尺寸和坐标，但不会判断角色是否像参考图，也不会识别所有视觉缺陷。导入成功后仍需看动作预览。

发现问题时，可以发送具体修复提示：

```text
请修复当前皮肤包的以下问题：
动作：[动作名称和 JSON 键]
可见问题：[例如向左走时脸型改变 / 第三帧脚被截断]
参考依据：[已确认定稿或预览中的具体位置]

保持已确认的角色身份与其他动作，重新制作有问题的动作行，
再按原网格重新组装，交付新的 PNG、匹配的 JSON 和该动作预览。
如果问题只是 JSON 与图片尺寸或帧位置不一致，
请先检查并修正配置；不要通过修改 EXE 或关闭校验来导入。
```

## 6. 导入与切换

v1.5 起，导入成功后可用“编辑动作配置”微调帧位置和时长、查看网格、配置注视方向，不必为简单参数修改重新生成图片。编辑器不会补画缺失动作，也不能修复角色画错或帧内画面不一致；这类问题仍需要 AI 重新制作素材。操作见 [动作配置编辑器](../README.md#动作配置编辑器)。

1. 准备单角色 ZIP，或同一目录内的 `pet.json` 和 PNG。v1.2/v1.3 用户需先解压 ZIP；v1.4 起可以直接导入。
2. 运行桌宠，在右键菜单或托盘菜单打开“设置”。
3. 选择“皮肤”页，点击“导入皮肤”。
4. 选择角色 ZIP 或目录中的 `pet.json`，不是普通 PNG 或预览动图。
5. 在动作下拉菜单中查看预览；点击“保存”应用到桌面。
6. 重新启动桌宠，确认仍使用所选角色。

导入后的两份文件保存在 `%APPDATA%\YeShunguangPet\Pets/<id>/`，程序升级不会覆盖。导入完成后可以删除原始下载目录。取消设置不会切换桌面角色，但已经导入的包会留在皮肤列表中。

也可以在 EXE 旁的 `Pets` 下放入完整的新皮肤文件夹，再点击“刷新”。每个角色应有独立目录和唯一 id。

v1.4 起，选中导入皮肤后可使用“更新皮肤”导入相同 id 的修正版，确认后保留旧文件备份；预览满意后保存。要分享角色，可使用“导出皮肤 ZIP”，它不会包含你的设置和日志。删除按钮只允许删除非当前使用的导入皮肤，随附角色受保护。详细备份与恢复规则见 [皮肤格式文档](PET_FORMAT.md)。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| AI 只给了一张立绘 | 还需要生成各动作画面、组装精灵图和配套 JSON；修改 JSON 不会补出动作 |
| AI 只给了一段 JSON | 还缺清单引用的真实 PNG 文件 |
| 导入窗口看不到 PNG | 选择配套 `pet.json` 或单角色 ZIP，普通图片不能直接导入 |
| 旧版导入窗口看不到 ZIP | 升级到 v1.4 或先解压，再选择 `pet.json` |
| 提示未知字段或 schemaVersion 错误 | 按 WPF [格式说明](PET_FORMAT.md) 生成清单；Codex 宠物清单不能直接用于本程序 |
| 提示 id 已存在 | 新角色使用独立 id；同角色修正版在 v1.4 中选中旧导入皮肤后使用“更新皮肤” |
| 提示尺寸不一致或坐标越界 | 核对 PNG 实际尺寸、单元格宽高、行列数量和动作有效帧数 |
| 有白底、黑底或棋盘格 | 检查 PNG alpha 通道，让制作工具输出真实透明背景 |
| 导入成功但动画闪跳或变脸 | 检查原动作画面与统一尺度、基线；软件格式校验不能替代视觉检查 |
| 走动、随机待机或注视不可用 | 检查对应动作是否提供；自动走动需要左右动作，注视需要 16 个方向 |
| 选择新角色后桌面没有变化 | 在设置中点击“保存”；仅预览或导入不会切换当前角色 |
