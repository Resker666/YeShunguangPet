# 角色行为规则（v2.8）

行为规则只声明空闲自动动作的候选、条件、相对权重和冷却，不执行脚本、不读链接、不访问系统命令，也不能改变拖动、菜单或退出等系统优先级。

## 界面配置

1. 打开“设置 → 皮肤 → 编辑动作配置 → 行为规则”。随附皮肤应另存为个人副本，不直接覆盖。
2. 开启“自定义自动动作”。首次开启时会填入当前皮肤可用的默认候选；之后可以添加、删除或修改。
3. 设置条件、动作、权重和冷却秒数。修改支持撤销/重做，非法内容会阻止保存与导出。
4. 保存皮肤副本或更新，再回到角色设置点击“保存”应用到桌面。角色的“随机待机”开关仍需开启。

关掉“自定义自动动作”恢复旧版默认选择；开启状态下删除全部规则则不再触发随机动作。删除后的空表不会因关掉再开启开关而自动补回。原始 PNG 文件不会被规则编辑修改。

## JSON 格式

在现有 `pet.json` 中添加可选成员 `behavior`。下面仅展示该成员，不是完整皮肤清单：

```json
{
  "behavior": {
    "schemaVersion": 1,
    "rules": [
      {
        "condition": "any",
        "action": "waving",
        "weight": 3,
        "cooldownSeconds": 30
      },
      {
        "condition": "cursorFar",
        "action": "jumping",
        "weight": 1,
        "cooldownSeconds": 60
      }
    ]
  }
}
```

| 字段 | 约定 |
| --- | --- |
| `schemaVersion` | 当前为 1 |
| `rules` | 最多 9 条；空数组表示没有自动动作候选 |
| `condition` | `any`、`cursorNear`、`cursorFar`，默认 `any` |
| `action` | `waving`、`jumping`、`failed`，默认 `waving`；必须存在、不循环且总时长不超过 30 秒 |
| `weight` | 整数 1-100，默认 1，相对于当前其他可选规则的权重 |
| `cooldownSeconds` | 整数 5-3600，默认 30，从该规则上一次被选中开始计算 |

同一条件和动作不能重复；未知字段、脚本字段、优先级字段、数字枚举别名、无效动作和空规则条目会被拒绝。该成员省略或为 null 时，继续使用旧版的打招呼/跳跃随机选择。

## 调度语义

- 先满足全局随机动作间隔（沿用原有随机浮动），再从条件匹配、冷却完成的规则中按相对权重选择。权重不是固定触发次数，也不是对所有时刻的概率承诺。
- `cursorNear` 使用现有鼠标接近半径，按光标到角色矩形的最近距离判断；`cursorFar` 为相反状态。这是到期检查时的位置条件，不是一次鼠标进入/离开事件。
- 若所有规则都在冷却，等待最早可用期限；若到期但位置条件不满足，进行有上限的短周期观察，不积压动作。
- 自动走动保留既有优先级。隐藏、收纳、输入处理中、拖动、菜单或设置打开时不执行规则；勿扰及启用“专注时暂停自动行为”时同样抑制规则。
- 手动动作、专注完成反馈等原有行为不由这些规则接管。规则动作也能被拖动等更高优先级交互中断。
- 相同规则重新载入保留运行中的冷却；规则实际改变或换成其他皮肤会重置该角色的规则冷却。退出程序后不恢复冷却。

含 `behavior` 的皮肤需要桌宠 v2.8.0 或更新版本。旧版会拒绝未知字段，需要兼容时另行提供省略 `behavior` 的清单。导入、备份、撤销、导出和热刷新继续执行整个皮肤包的原有安全验证。

## 配合诊断

从控制中心的“设置 → 应用 → 诊断与日志 → 活动采样”开始采样后，可查看规则命中、冷却中、条件未满足或默认选择。界面规则编号从 1 开始；诊断 JSON 的 `RuleIndex` 从 0 开始，-1 表示没有所选规则。

没有动作时，先检查随机待机开关、全局间隔、当前活动状态和冷却，不要通过缩短所有间隔或增加优先级字段来绕开交互保护。
