## 发布前顺序

1. 确认 README、演示素材、体验反馈表单和文档链接无误。
2. 提交并推送这些文档改动，再确认 GitHub 页面上的图片、GIF、下载入口和反馈表单都能打开。本次没有程序功能变化，不需要为推广重新发一个应用版本。
3. 更新仓库简介、Topics 和分享封面，步骤见元数据文档。
4. 在一台没有开发环境的 Windows x64 电脑上，从 Release 下载完整 ZIP，确认下载、解压、启动和退出流程。
5. 检查每张公开图片：不能出现个人桌面、聊天记录、公司文件、账号、路径或密钥；确认素材来源及适用的分发条件。
6. 先在一个主要内容平台发布。社群分享先确认管理员和版规允许；不要批量刷屏、私信陌生人或要求关注后才给下载。

发布动作需要项目维护者确认账号、素材和正文。本文件不是“已发布”记录，也不包含任何增长保证。

## 首轮试用与回访

先给参与者项目主页，不做口头代操作。记录他能否自己找到下载、完整解压、启动角色、打开计时与退出。如果卡住，先记录卡点，再提供帮助；不要把被指导后的完成当作独立完成。

第一次只问：

1. 能否顺利启动？卡在哪一步？
2. 实际试了哪一个功能？
3. 最希望改的一点是什么？

只有愿意回访的人，才在同一反馈渠道于 3–7 天后再问：有没有再次打开？为什么继续用或没有继续用？不用另外索取手机号、邮箱或真实姓名。

GitHub 用户可用[体验反馈表单](https://github.com/Resker666/YeShunguangPet/issues/new?template=trial_feedback.yml)；其他用户直接回复原帖。不要为了反馈要求用户加入私群、关注账号或公开完整日志。

## 如何选下一版

- 多人找不到下载入口：先修展示和下载流程，不加更多角色功能。
- 多人卡在解压、文件缺失或安全提示：先处理分发与首次运行，不让他们关闭系统保护。
- 能启动但找不到常用操作：优先调整入口和默认设置。
- 经常使用迷你钟但不知道新版：考虑检查更新入口。
- 只有具体功能反复被真实用户提到时，再安排该功能；不因一条随口建议立即扩大战线。
