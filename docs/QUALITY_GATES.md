# 质量门禁

本轮首先覆盖计时链路，沿用现有 .NET 8 / Windows x64 测试程序，不需要额外测试包、账号或真实用户数据。测试只创建隔离的日志和测试状态；窗口循环使用不可见的测试窗口，不读取个人桌面截图，不写启动项。

## 本地运行

在仓库根目录使用 PowerShell，先运行完整回归：

```powershell
dotnet build --configuration Release
dotnet run --project tests/PetTests.csproj --configuration Release -- . artifacts/qa
dotnet run --project tests/PetTests.csproj --configuration Release --no-build -- . artifacts/ui-smoke --ui-smoke
dotnet run --project tests/PetTests.csproj --configuration Release --no-build -- . artifacts/quality --quality
```

质量模式独立运行控制器契约、随机序列、性能、截图和窗口生命周期检查。退出码不为 0 就是失败，不以“有输出图片”判断成功。

额外延长窗口循环，例如 3 分钟或 30 分钟：

```powershell
dotnet run --project tests/PetTests.csproj --configuration Release --no-build -- . artifacts/quality-soak --quality 180
dotnet run --project tests/PetTests.csproj --configuration Release --no-build -- . artifacts/quality-soak-long --quality 1800
```

时长范围为 0-7200 秒；0 表示至少 30 次窗口循环，不表示跳过。计时使用可控时钟，因此无需实际等待一次 25 分钟专注。长循环测的是反复打开、切换和关闭面板的资源回收，不等同于整机多小时真实使用。

## 检查内容

| 门禁 | 方法 | 默认预算/要求 |
| --- | --- | --- |
| 控制器契约 | 不创建窗口，验证输入、失败回退、命令锁、保存顺序和 Dispose | 全部通过 |
| 随机状态序列 | 32 个固定种子，每个 4,000 步，与独立减法计时模型逐步对照 | 128,000 步全部一致 |
| 截图回归 | 完整/紧凑/迷你 x 浅色/深色，96 DPI 固定客户端、关闭装饰动画 | 平均差异 <= 0.035；高差异块比例 <= 8%；最差局部区域 <= 0.10 |
| 窗口释放 | 预热后循环真实 WPF 窗口，保持 Runtime 存活，回收后检查弱引用 | 窗口和控制器残留为 0 |
| 内存增长 | 循环前后多轮 GC + Dispatcher 排空，取进程数据 | 托管 <= 16 MiB，Private Bytes <= 64 MiB |
| 原生资源 | 比较进程句柄与 USER/GDI 对象 | 增长分别 <= 64 / 16 / 32 |
| 热路径分配 | 25 万次快照、10 万次缓存帧、10 万次轮询 | 每组 <= 1 MiB，单组 <= 10 秒 |
| 显示格式化 | 2 万次时间与状态文案 | <= 16 MiB，<= 10 秒 |

内存为暖机后增长预算，不是整个程序的内存上限。耗时预算故意留足 CI 机器差异，主要防止严重退化；报告保留实测值用于比较，不是精确微基准或帧率承诺。热缓存检查不代替原有后台首次解码测试。

截图检查关闭动画以保持基线稳定；生命周期循环则启用动画，覆盖头像计时器和模式过渡的释放。截图门禁还检查纯背景不能被接受，避免空白画面也“通过”。

## 失败定位与重放

- `quality-report.json`：版本、运行环境、通过状态、已完成阶段数据与异常。
- `sequence-failure.json`：随机种子、失败步、最近 32 条操作。
- `lifecycle-report.json`：窗口循环次数、实际时长、内存/句柄采样及预算。
- 六张 `*-light.png` / `*-dark.png`：本次实际渲染图，失败时也保留已生成的图。

按失败种子完整重放，例如：

```powershell
dotnet run --project tests/PetTests.csproj --configuration Release --no-build -- . artifacts/quality-replay --quality 0 250000
```

种子重放依赖相同测试代码与 .NET 主版本。固定序列让 CI 可复现，但不覆盖所有可能顺序；新增故障应同时补充简短的命名回归用例。

## 截图基线管理

`tests/baselines/focus` 的 6 张 PNG 随 v2.9.0 的专注计时界面调整重新记录并逐张复核，覆盖完整/紧凑/迷你布局及深浅主题。旧版 v2.4 基线保留在 Git 历史中。这些是测试窗口渲染图，不是修改过的角色素材。对比排除系统标题栏；每个 8x8 块计算 RGB 差异，允许字体抗锯齿的小幅变化。另按 32x32 区域检查局部差异，防止缺失的控件被大片空白区域稀释。

只有有意改变界面且人工确认时才显式重录：

```powershell
dotnet run --project tests/PetTests.csproj --configuration Release --no-build -- . artifacts/baseline-review --record-focus-baselines
```

逐张检查后把基线更新与对应 UI 修改放在同一个提交里。不要在 CI 中执行重录，也不要为了让失败变绿直接替换基线。尺寸变化直接失败；屏幕 DPI、可点击范围和倒计时布局仍由原有原生 UI 用例补充。

v2.9 原生回归另检查：迷你钟在 280x104、320x104、旧尺寸 320x128、480x200 下的最长倒计时和控件边界；标题/时间左对齐、标题旁头像及状态互不重叠；专注/暂停/完成/休息与保存失败文案；常规字重、等宽数字、头像悬停与无障碍名称随角色更新；完整面板的 320x460、400x560、600x720 布局与中性入口文案。迷你基线按新默认 320x104 记录。拖动排除按钮、圆环和输入框，保留头像、标题、状态和空白区域；旧尺寸、位置与置顶偏好保留，新最小高度可持久化，旧历史格式不变。

## CI 与发布

Build / Release 在原有功能和原生 UI 检查之后执行质量模式，最长允许 10 分钟。`quality-diagnostics` artifact 在失败时也上传已有报告和测试渲染图，保留 7 天。

任一门禁失败，后续应用包上传和 GitHub Release 步骤不会执行。诊断 artifact 与公开便携 ZIP 分离，不把测试截图发到 Release。推送前的本地通过不代表云端已通过；最终以对应提交的 Actions 结果为准。

当前不覆盖断电、数小时挂起、所有显卡驱动、多显示器热插拔及真实用户输入的所有时序。不要把短循环结果解读为“没有任何内存泄漏”。

## 编辑器回归（v2.6）

核心测试增加编辑历史、无效输入恢复、批量时长、时间轴边界、保存冲突和后台文件快照检查。`--ui-smoke` 同时执行编辑器的原生布局与源文件刷新流程，也可单独运行：

```powershell
dotnet run --project tests/PetTests.csproj --configuration Release --no-build -- . artifacts/editor-smoke --editor-smoke
```

检查内容包括深浅色的 1020x760、800x560 窗口，源文件半写入、损坏 PNG、ID 冲突、目录整体替换、保留草稿、手动检查及关闭时取消。渲染图输出为 `editor-advanced-*.png`，用于人工检查，不自动替换计时器基线。

生命周期检查验证监听器与播放计时器关闭、迟到结果不再改变窗口，并在新编辑器打开时检查前一批 10 扇关闭窗口是否可回收。综合原生测试环境中，最近一扇关闭窗口可能延迟到下次打开编辑器才释放；该用例检查连续开关是否累积旧窗口，不承诺每一扇窗口关闭瞬间立即回收。创建窗口和检查弱引用的方法禁止内联，避免测试本身保留临时强引用。

## 角色行为回归（v2.7）

核心测试加入 `PetBehaviorController` 和 `SpritePlayback` 的确定性用例，包括暂停恢复、循环边界、迟到回调、长时间停顿、系统时间校正、优先级、能力缺失和游走预算。16 个固定种子各执行 4,000 次操作，检查互斥关系及活动许可；失败信息包含种子、步骤和最近操作编号。

`--ui-smoke` 增加三角色检查：原生图像与预期帧一致，隐藏时停止角色计时器，恢复时保留进度，菜单/勿扰/专注正确抑制自动工作，手动动作结束后回到共享专注状态，以及贴边后不重复构建未变化的视图。

热路径测试检查 100,000 次预热后的帧采样分配预算。完整 CPU/回调对比使用 [角色性能探针](ACTIVITY_PERFORMANCE.md)，不把不稳定的短样本 CPU 百分比设为 CI 硬阈值。既有功能测试、原生 UI 测试和计时质量门禁继续运行。

## 规则与采样回归（v2.8）

核心测试覆盖规则版本、未知字段/条件、数字枚举、动作白名单、缺失引用、超长动作、数量/权重/冷却边界、重复规则、复制后的权重选择、冷却保持、系统优先级和空规则语义。编辑器用例验证规则编辑、非法输入、删除及撤销/重做；保存与载入检查 PNG 字节不变。

采样用例验证默认关闭、手动开始、多个订阅者独立释放、匿名编号不复用、角色退出、五分钟上限、队列容量和导出字段。原生 UI 回归覆盖深浅色和 510x450/800x640 诊断窗口、紧凑规则编辑器，以及实际桌面角色采用规则并产生命中记录。截图仅来自测试窗口渲染。

## 快捷键与视觉一致性（v2.10）

功能测试新增 ShortcutTests：旧配置默认值、组合白名单、重复、配置读写、注册与保存失败回退、命令互换、启动失败重试、配置副本隔离和退出释放。另用两个测试窗口暂时注册一个可用组合，验证真实 Windows 占用、释放与重试，不发送真实按键，也不覆盖其他应用的组合。

原生 UI 测试新增 ShortcutUiTests：深浅主题、580x650 默认窗口无滚动、480x460 小窗口可滚动到最后一项、保存/取消/恢复默认、可见且不改变尺寸的焦点边界、当前快捷键提示，以及使用 Dispatcher 模拟消息处理的计时草稿/模态/旧代次保护。测试仅使用独立配置与注册器，默认不会修改个人设置。

已有窗口测试同时验证共享系统字体与文本格式化；计时器保持 v2.9 的布局，沿用原有截图比较阈值，不为新功能放宽质量预算。

## 截图与完成提醒（v2.11）

`CaptureTests` 覆盖负坐标、反向拖动、物理像素取整、区域越界、大小上限、源像素不变、裁剪/遮挡合成、PNG 扁平输出、标注和历史上限、贴图数量，以及完成提醒的生成、去重、确认、勿扰和通知关闭。

`CaptureUiTests` 通过注入图像与坐标验证每屏一个选区窗口、跨屏选择、取消和关闭、1000x720/720x480 编辑器、实际画布手势、剪贴板占用、保存和贴图、临时可见性恢复及退出取消；关闭编辑器与贴图后检查弱引用回收。测试不写个人剪贴板、不保存个人桌面。

真实 GDI 读取用例只截取自建纯色测试窗口的内部小块，并先检查交互桌面是否可访问。如果当前隔离环境或 CI 没有输入桌面权限，该项打印明确的 SKIP，其余合成图像与窗口回归仍执行。这不等于已经验证真实桌面捕获，发布前仍需在普通 Windows 桌面测试实际框选、混合 DPI、多屏及显示器热插拔。

完成提醒测试覆盖服务状态、真实 WPF 角标属性、托盘图标模型与点击确认，不读取用户任务栏截图。角标在各 Windows 任务栏设置下的最终外观需实际设备验收；既有计时器截图基线和性能预算不放宽。

可单独运行截图界面用例：`dotnet run --project tests/PetTests.csproj --configuration Release -- . artifacts/capture-smoke --capture-smoke`。完整 `--ui-smoke` 也会执行同一组用例。

原地浮层回归增加 `InlineCaptureUiTests`：松手后保留选区、八手柄和边缘命中、移动边界、扩大选区后的原像素、原地文字、上下文参数不挪动主工具行、整屏精确范围、剪贴板/保存/贴图失败保留、窗口回收。`inline-*.png` 是对独立测试控制中心的合成预览，不是用户桌面截图。默认流程不再打开独立编辑器，旧编辑表面只作为共享绘图能力的回归工具。
