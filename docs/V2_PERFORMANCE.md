# v2.0 多角色与性能验证

## 范围

本版支持最多 3 个独立角色实例，不是启动 3 份程序。皮肤包仍为 `schemaVersion: 1`，原始 PNG 文件未改变。

- `DesktopSession`：管理角色实例、单一托盘和快捷键、全局设置、应用退出。
- `CompanionRuntime`：单一学习计时、提醒调度和学习面板；角色关闭只解除自身订阅。
- `MainWindow`：实例自己的动画、拖动、位置、缩放、穿透和四边收纳。
- `DesktopSettingsStore`：首次迁移旧设置，独立保存 `desktop-v2.json`，保留旧 `settings.json` 和上一版 v2 `.bak`。
- `SpriteCache`：按 PNG 字节的 SHA256 共享冻结图片；最多 64 个非活跃弱引用索引，每张图片最多缓存 256 个帧矩形。活跃实例持有租约，不受弱索引淘汰影响，关闭时释放。

可见角色的帧计时仍独立运行，共享图片不共享可变动画状态。全部隐藏后角色自己的 4 类定时器停止，共享学习时钟保留。收纳把手可见时仍需检测悬停，不等同于完全隐藏。

## 环境与口径

测量日期：2026-09-07 至 2026-09-08；Windows NT 10.0.26200，x64，14 个逻辑处理器，.NET 8。

CPU 指标为 `进程 CPU 秒 / 经过秒数 × 100`，100% 表示用满一个逻辑核心，不是任务管理器显示的整机百分比。内存区分托管分配、托管堆、私有内存和工作集，不能相互替代。

素材测试使用同一叶瞬光 PNG、同一组参数：先预热一次，再同时保留 3 个相同皮肤包，发出 9000 次帧请求。v1.5 基线是在缓存改动前采集的一次结果；v2 为最终代码的 3 次独立进程测量，中位数如下。样本量小，结果只说明这组负载，不代表通用性能保证；冷启动受文件缓存与 JIT 影响，不据此声称启动速度提升。

| 指标 | v1.5 基线 | v2 中位数 |
| --- | ---: | ---: |
| 三个相同皮肤的解码图片数 | 3 | 1 |
| 三次加载总时间 | 344.10 ms | 78.30 ms |
| 三次加载托管分配 | 67,297,928 B | 37,348,184 B |
| 9000 次帧请求时间 | 33.11 ms | 2.09 ms |
| 帧请求托管分配 | 5,348,696 B | 3,416 B |
| 探针结束强制 GC 后私有内存 | 97.20 MiB | 40.21 MiB |

v2 三次加载时间范围 74.45–83.36 ms。上述测试不创建桌面窗口，不能把这里的私有内存当作整个桌宠的运行内存。

## 真实窗口采样

使用独立内存配置，不读写真实用户的桌面配置；50% 大小、非置顶、点击穿透，关闭随机动作、漫游与鼠标注视。先预热约 2 秒，然后每个阶段约 30 秒。后两个角色为另一随附角色及一个叶瞬光副本。窗口未强制置顶，因此外部遮挡和 GPU 合成负载未完全控制。

| 阶段 | 单核 CPU | 私有内存 | 工作集 | 角色定时器数 |
| --- | ---: | ---: | ---: | ---: |
| 1 个显示 | 2.22% | 144.79 MiB | 213.01 MiB | 1 |
| 3 个显示 | 5.22% | 179.70 MiB | 249.67 MiB | 3 |
| 3 个全部隐藏 | 0.41% | 180.59 MiB | 250.70 MiB | 0 |

可见阶段观测到图像帧变化；三个角色的 WPF 自身视图渲染均通过非透明像素检查。隐藏阶段帧变化为 0。隐藏不立即卸载皮肤，因此内存不会随隐藏立刻下降，目的是保留快速恢复能力。

原 v1.5 用户进程另有一次 30 秒被动观测，约 2.17% 单核 CPU。该会话状态、历史操作和窗口条件没有控制，不能与上述 v2 受控采样直接比较，也不能据此断言旧版存在泄漏。

## 生命周期与原生检查

- 150 次创建、订阅共享计时、关闭的 WPF 角色对象循环后，仍存活的被测角色弱引用为 0，图片租约为 0。
- 这 150 次循环没有逐次显示原生窗口。真实显示与关闭验证覆盖前面三个窗口，不能把对象循环当作 150 次完整桌面窗口压力测试。
- 最终循环前后托管堆约为 9.41 MB 与 1.77 MB；强制 GC 后的有限样本不等于长期无泄漏证明。
- 独立原生冒烟测试实际创建托盘及快捷键窗口，全局快捷键注册成功。
- 重复打开学习陪伴仍只有一个面板，移除所有角色后共享专注计时继续。
- 配置迁移、原子保存、零角色重启、实例数量限制、皮肤使用保护、不同内容缓存失效、缓存淘汰、保存失败退出等通过回归检查。

## 复现

在仓库根目录执行，开发机需要 .NET 8 SDK。`dotnet` 不在 PATH 时替换为实际 SDK 路径。

```powershell
dotnet run --project tests/PetTests.csproj --configuration Release -- . artifacts/qa-v2.0.0
dotnet run --project benchmarks/PerformanceProbe.csproj --configuration Release -- . artifacts/performance-v2/repeat-assets.json
dotnet run --project benchmarks/PerformanceProbe.csproj --configuration Release -- --live . artifacts/performance-v2/repeat-live.json 30
dotnet run --project benchmarks/PerformanceProbe.csproj --configuration Release -- --native-smoke . artifacts/performance-v2/repeat-native.json
```

`--live` 最后的数字是每个阶段的秒数，总计约三倍加清理时间，默认 30；可使用 300 做约 15 分钟的分段采样。它会临时显示测试角色，结束后自动关闭。`--native-smoke` 还会临时创建托盘并打开学习面板，测试前先退出其他桌宠版本，避免占用相同快捷键。不要用 3 秒原生冒烟数据评价稳态 CPU。

`scripts/measure-process.ps1` 可被动采样指定进程，不控制其显示状态。完整测量 JSON 和各角色自身的渲染 PNG 位于本地 `artifacts/performance-v2`，不自动上传，也不包含其他应用的桌面截图。需要复现旧版基线时，应在独立的 v1.5.0 源码副本中运行等价素材负载，不能拿新版探针结果冒充旧版。

## 待人工验收

1. 添加叶瞬光、知更鸟和同皮肤副本，逐个拖动、缩放、换肤，确认其他实例参数不变。
2. 将不同实例停靠在不同边缘，分别隐藏、展开和关闭；快捷键应召回全部，托盘保持一份。
3. 开始学习后关闭其中一个角色，再关闭全部角色，确认面板计时继续且完成通知只有一次。
4. 重启程序，确认角色数量、独立位置、大小和隐藏状态恢复；旧 `settings.json` 不变。
5. 在不同 DPI 的显示器间拖动，拔插外接屏，检查收纳、尺寸和位置；当前自动测试只覆盖坐标模型和本机窗口，不宣称覆盖所有显示器组合。
6. 睡眠唤醒、Windows 注销或关机重启，以及连续数小时运行后检查计时、窗口、句柄和内存趋势。本轮未执行这些长时间或系统级场景。

出现问题时请提供具体操作顺序和本地日志；上传日志前移除不希望公开的路径等个人信息。
