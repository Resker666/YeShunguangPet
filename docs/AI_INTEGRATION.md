# AI 接入架构

从 v2.18.0 起支持角色人设、连续聊天、台词建议和专注总结。AI 仅在用户主动请求时联网，不读取屏幕。

## 角色聊天与人设

1. 控制中心左侧「AI 设置」配置并启用服务；已有配置可继续使用。
2. 右键桌面角色 →「聊天」→「角色人设」，填写背景、性格、说话习惯和示例台词，点击「保存人设」。初次打开会用皮肤自带介绍填入背景，用户可以修改。
3. 切换到「聊天」，输入消息并点击「发送」，或按 Ctrl + Enter。Enter 换行。
4. 人设也用于「角色台词 → AI 生成当前台词」；台词窗口的「角色人设」按钮可直接编辑。

每次发送会提供已保存的人设、该角色最近最多 12 轮完整对话以及本次输入。各角色按皮肤 ID 分开存储，同一皮肤的多个桌面实例共用人设和记录。不同角色不会互相带入记录。

人设和最近聊天记录以普通 JSON 保存在用户设置目录的 `ai-characters` 子目录，重启后保留；API Key 仍使用独立的 Windows 加密存储。聊天不写入皮肤文件，不加入日志或诊断包。

「清空记录」删除当前角色保留的本地对话并保留人设，不代表删除服务商端可能保存的数据。停止或失败的请求不加入历史，输入草稿保留供重试。生成回复成功但本地保存失败时也会明确报错，不把未保存结果当作已保存。

本轮实现为完整回复模式，支持停止请求和失败重试；尚未实现逐字流式显示、自动长期记忆及聊天回复一键转台词。消息最多 2000 字符，回复最多 8000 字符。

## Provider 层

程序使用 `IAiProvider` 抽象 AI 服务，未来可以切换：

- **Direct**：桌面端直连 OpenAI-compatible API。API Key 使用 Windows DPAPI 加密保存，不写入 `desktop-v2.json`。
- **Relay**：桌面端请求自建中转服务，服务端保存真正的模型 Key，适合公开分发。
- **Local**：连接本机模型服务，例如 Ollama 或 LM Studio，不需要云端 Key。

当前所有 Provider 默认关闭。未配置 AI 时，桌宠、计时、皮肤和台词功能保持完整离线运行。

## 建议层

`AiSuggestionService` 只接收结构化建议，不允许模型直接：

- 执行脚本或命令；
- 修改皮肤文件；
- 改写桌面配置；
- 自动读取屏幕或上传截图；
- 直接触发角色动作。

建议必须经过长度、动作枚举和时长范围校验，再由本地程序决定是否展示或执行。

## 推荐演进顺序

1. AI 生成角色台词和鼓励语。
2. AI 根据本地专注记录生成每日总结，发送前明确提示数据范围。
3. AI 生成行为规则草稿，由用户确认后写入皮肤配置。
4. 需要公开分发时，再增加 Relay Provider、账号、限流和费用控制。

不要把 API Key 写入源码、日志、皮肤包、GitHub Release 或普通 JSON 配置，也不要把完整桌面截图作为默认请求内容。
